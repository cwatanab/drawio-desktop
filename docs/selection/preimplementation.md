# 透明なグループ・コンテナの選択改善：実装前の整理

対象Issue: https://github.com/cwatanab/drawio-desktop/issues/1

これは実装前の記録です。実装内容と検証結果は [implementation.md](implementation.md) を参照してください。

見えている子を直接選択し、透明な空白から背面選択や範囲選択を行えるようにする。既存の選択・移動機能を利用し、クリック判定と親子選択の規則を変更する。

## 既存機能と必要な差分

- `Graph.js:12826`：`transparentBounds`は明示的なスタイル値で判定する。塗りなしや不透明度0%から自動判定しない。クリック通過と枠の自動サイズは別の仕様として扱う。
- `Graph.js:24893`：transparentBoundsの境界では子を直接選べる。`selectParentFirst=1`は親優先になり、通常グループにも適用される。
- `Graph.js:11524`：選択済みの子を再クリックするとtransparentBoundsの親へ選択が移る。今回の通常クリックの一貫性と差分がある。
- `Graph.js:12838`：移動アイコンはtransparentBoundsで既定表示、それ以外も`moveIcon=1`で有効にできる。新しい移動機構を作る前に利用範囲を確認する。
- `Graph.js:24981`付近：子の選択時、transparentBoundsの祖先にもハンドルを作る。ただし、未選択の子へのホバーだけで全階層のハンドルが表示されることは確認できていない。
- `grapheditor/Editor.js:404`、`Graph.js:18843`付近：`defaultTransparentGroups`の既定はfalse。trueの場合、新規グループにtransparentBoundsを付ける。既存グループの一括変換を意味しない。
- `mxShape.js:1095`：塗りなしでも、pointerEvents未指定ではcanvasのイベントを無効化しない。`pointerEvents=0`との比較が必要。描画時の設定だけでなく`getCellAt`などの座標検索も検証する。
- `Graph.js:11524`、`Graph.js:24865`付近：lockedGroupの子の選択・ドラッグ開始はロックされた祖先へ向ける。子を個別編集させない既存規則を守る。

## 実装案として採用する操作規則

1. 通常クリックは選択可能な子を優先する。透明な親の空白は通過し、背面にも対象がなければ選択を解除する。同じ空白からのドラッグは範囲選択にする。
2. 親の枠線・タイトルに子が重なる場所では子を優先する。親だけの枠線・タイトルなら親を選べる。親の明示的な選択ハンドルは最優先とする。
3. 入れ子はホバー対象から祖先までの補助枠・ハンドルを表示する。ハンドルが重なる場合は外側へずらし、ホバー時に親名と階層を示す。子から親のハンドルへポインターを移しても表示を維持する。
4. 選択した背面図形は移動ハンドルから確実に動かせるようにする。重なった前面図形を通常クリックした場合は、その前面図形へ選択を変更する。
5. `lockedGroup=1`の中身は個別選択・移動しない。親を選択して一体として扱う。移動自体を禁止するロックやレイヤーロックは別物であり、それぞれの禁止を優先する。
6. Shiftなどによる既存の複数選択、ダブルクリック編集、線の接続操作を維持する。「同じ位置で同じ対象」の規則は修飾キーなしの通常クリックに適用する。
7. 透明扱いは塗りなし・塗りの不透明度0%。半透明は通過しない。グループの自動境界化は別設定として維持し、既存図形の保存座標や前後関係を選択改善のために書き換えない。
8. 適用対象では通常クリックの親子循環を停止する。`selectParentFirst=1`などの明示的な既存指定は互換動作として尊重し、仕様の例外とする。

上記は実装上の判断を進めるための案。特に親子が重なる位置と、明示的な親優先指定の例外は、先のIssue本文に対する具体化となる。

## 再現図と手動確認

- 01：塗りなしのコンテナ。子B、親Aの空白越しの背面C、空白からの範囲選択。
- 02：01にpointerEvents=0を設定した比較。DOMイベントと座標検索で対象が一致するか。
- 03：塗り色あり・fillOpacity=0。01と同じ通過挙動になるか。
- 04：fillOpacity=30。透明扱いせず、面を選べるか。
- 05：通常グループ。直接選択と既存の親優先選択の差分。
- 06：transparentBounds。子の再クリック、親のハンドル、子の縮小・削除と枠の追従。
- 07：selectParentFirst=1。明示的な互換動作を維持できるか。
- 08：lockedGroup=1。子を個別に選択・移動しないか。
- 09：入れ子。孫の直接選択と内側・外側の親の選択、ハンドルの重なり。
- 10：背面図形の大部分を前面図形が覆う。背面のmoveIconから意図した対象だけを移動できるか。

各ページで50%・100%・200%のズームを確認する。選択直後のドラッグ、Shiftで追加・解除、ダブルクリック編集、接続点への線の追加、Esc、Undo/Redo、保存・再読込も確認する。範囲選択時に親子を同時選択して二重移動しないかを含める。

GUI確認後、枠線・ハンドルの当たり判定幅を画面上のピクセルで決める。現時点で根拠のない数値は固定しない。

## 実装を始める順序

1. GUIが起動する環境で再現図を開き、上記項目の現行結果を記録する。
2. pointerEventsによるクリック通過と座標検索結果の違いを調べる。
3. 通常クリックと範囲選択を変更し、その後にホバー時の親ハンドルを追加する。
4. 06・07・08の既存機能との整合性を確認する。
5. クリック判定・親子循環・ロックの回帰テストを必要な範囲で追加し、手動確認を完了する。
