# 階層ビューア・Quick Stylerの使い方と検証

本ブランチの実装を試す人向けのメモ。初回は「有効化する」を読み、操作・検証の節は必要に応じて参照する。機能の詳細は[仕様書](specification.md)に記載した。Windows実機の確認が残っているため、受け入れ条件全体の完了扱いにはしていない。

## 有効化する

依存関係を導入済みのリポジトリで `npm start` を実行する。

1. 「その他 → プラグイン」を開き、「追加」を選ぶ。
2. 階層ビューアは `hierarchy`、Quick Stylerは `quickstyler` を選んで追加する。片方だけでも使える。
3. ダイアログを閉じ、アプリを終了して起動し直す。

初期状態では両方とも無効。有効化後、右側の「書式／階層」で表示を切り替える。Quick Stylerは図形を右クリックしたときの「プロパティ」「スタイル」から使う。無効化するときも同じ設定画面で対象を削除して再起動する。保存済みスタイルは削除されない。

## 一覧から選択・編集する

階層の上側ほど同じ親の中で前面にある。行のクリックで選択し、ShiftまたはCtrlクリックで選択を追加・解除する。レイヤー行は作業対象レイヤーの切替になる。

名前は鉛筆ボタンまたはF2で編集する。Enterで確定、Escapeで取消。装飾を含む名前は既存のラベル編集に渡す。丸い表示ボタンは図データの表示状態を変更するため、Undoの対象になる。

左端のハンドルをドラッグすると、一行だけ移動できる。行の上端30%は前面、下端30%は背面への挿入、中央40%はグループ・コンテナ・レイヤーへの移動になる。拒否理由は一覧の下に表示する。ロックや表の行・セルなどの制約は[仕様書第6章](specification.md#6-ドラッグで順序を変えても図形を飛ばさない)を参照。

「スタイル → スタイルを管理」では、右クリックした図形を保存元として名前を付ける。保存済みスタイルの適用先はメニューを開いた時点の選択図形。外観だけでなく移動・編集などの設定も保存対象になる。

## 回帰テストを実行する

GUIテストには画面が必要。Linuxの画面なし環境ではXvfbなどを起動し、`DISPLAY` を指定する。テストは一時プロファイルを作成し、普段の設定を変更しない。GUIテスト同士はフォーカスが競合するため、順番に実行する。

```sh
npm test
npm run test:plugins-gui
npm run test:plugins-gui -- --source
npm run test:selection-gui -- --bundled
npm run test:selection-gui
```

プラグインのテストは実際のDesktopエントリーポイントを使い、HTTP/HTTPS通信を遮断する。無効、単独、併用、再無効化、逆順での併用を、同じ一時プロファイルでプロセスを再起動して確認する。`--source` では追加で `dev=1` のソース版へ移り、テスト用に両プラグインを明示的に読み込む。開発モードは設定プラグインを自動で読み込まないため、通常版の検証とは区別する。

実行後に出力される一時ディレクトリには、階層のライト・ダーク・狭い画面と、スタイル管理ダイアログの画像を保存する。失敗時はコマンドの出力、画像、再現操作をこの変更の担当者へ共有する。

## 実装範囲と残る確認

同梱プラグイン2ファイルと `App.pluginRegistry`／`App.publicPlugin` の登録を追加した。既存のFormat、メニュー、モデル更新、Undoを利用し、汎用ドッキング基盤や追加依存は設けていない。`App.js` の登録変更は既存のAntビルドで `app.min.js` に反映した。

ソース版の検証で、`bootstrap.js` のDesktop用2ファイルが存在しない `js/desktop/` を参照している問題が見つかった。この2か所を通常版と同じ `js/diagramly/` に修正した。外部プラグイン読込やセキュリティ設定は変更していない。

2026-09-11時点の確認環境はLinux ARM64、Electron 44.2.0。通常版・ソース版のプラグインGUIテストは、それぞれ283項目と再起動6構成が通過した。専用ハンドルからのネイティブHTMLドラッグ、Quick Stylerでの変更後のドラッグ可否、既存の書式編集も確認した。日本語入力はcompositionイベントとキー入力で確認しており、OSのIMEを使った手動検証ではない。

既存の選択GUI回帰テストも通常版・ソース版で各567項目が通過した。`npm test` の5テスト、追加・変更したJavaScriptの構文検査、差分の空白検査にもエラーはなかった。

Windowsでは次を実機で確認する必要がある。Linuxでの結果だけでは[受け入れ条件11](specification.md#10-両機能の単独動作と併用を確認する)を満たさない。

- 通常起動で両プラグインを有効化し、右サイドバーの表示切替・ウィンドウサイズ変更・書式との切替で重なりが生じないこと。
- マウスで専用ハンドルをつかみ、上下への並べ替え、グループへの出入り、レイヤー間移動ができること。位置が保たれ、一回のUndoで戻ること。
- 禁止対象に落とした際に図が変化しないこと。ライト・ダークの操作名が読め、日本語IMEで名前やスタイル名を誤確定しないこと。

確認結果にはWindowsのバージョン、使用したコミットまたは変更内容、成功した操作と不具合を記録する。Windows配布物のビルド、コミット、公開は実施していない。

用語: 同梱プラグインはアプリに付属する追加機能、プリセットは名前付きの保存済みスタイル、Undoは図の変更を一操作ずつ戻す機能を指す。
